# 更新记录

## 1.0.0

首个可交付版本：Issue 指派给 AI 编码 Agent（Codex CLI、TRAE CLI 2.x），在各自机器上的 daemon 中执行；工作流组件化编排（指派即执行、评论续聊、实现 ⇄ 评审循环、人工审批、推送分支、定时体检）；React 前端、`orca` 命令行、一键安装与 `doctor` 自检、审计日志。

### 安全

- **审批策略改为白名单**（被批准的命令在沙箱外执行）：
  - 命令的工作目录按真实路径（跟随符号链接）必须在工作区内；`cd` 只能回到工作区根目录。
  - 内置 git 命令（`add / commit / status / diff / log / show / rev-parse`，以及只列出分支的 `branch`）逐个列出允许的选项，git 接受的长选项缩写因此无法绕过；路径参数必须在工作区内。
  - 工作区内存在嵌套仓库（任何大小写、带结尾点或空格的 `.git`）时不批准任何 git 命令；daemon 排除的依赖目录（`node_modules` 等）不扫描，`git add -f` 不批准。
  - 白名单中的 `git push` 只能把 `orca/*` 分支推到 `origin`，不允许 `--force`、`--delete`、`--mirror` 或其他远端地址。
  - 只“允许一次”；人选“本任务内允许”时由 daemon 记住（命令 + 目录，任务结束即失效），CLI 只收到“这一次”。
- **TRAE**：不使用 `--allowed-tool`（匹配的命令会被直接在沙箱外执行）；从不选择“不再询问”（会写成整机规则）；不再把任务目录写入受信任列表。`orca-daemon doctor` 检查旧版本遗留的规则。
- **Codex**：给运行中命令写入输入（`writeStdin`）的请求一律拒绝，不按原命令判断。
- daemon 自己执行的 git 关闭 hooks、fsmonitor 与 `ext::` 协议。
- `X-Forwarded-For` 只信任 `ORCA_TRUSTED_PROXIES` 所列代理；失败登录审计设上限并记录省略条数。

### Codex 驱动

- 取消评审会中断实际运行的子轮次（此前取消无效）。
- 续接会话时以重放的累计用量为基线，`taskTokens` 只计本任务。
- 轮次启动阶段与两轮之间到达的取消不会丢失。
- 评审进行中不能插话（Codex 拒绝），改为提示评审后评论，评审结论不会被覆盖。
- 只有“线程不存在”才改为新开会话；崩溃或超时照常报错，不丢弃原会话。
- 带说明的评审改走 custom 目标；评审模型与 Agent 一致；服务端的占位提示不改变评审目标。
- 错误码保留原意：模型不存在、限流、预算用尽不再自动重试。

### TRAE 驱动

- 系统提示词说明 `.git` 只读与提交方式，TRAE 会直接申请提权完成提交。
- 被拒后自动续跑共用原超时、保留 JSON 输出要求，用尽时报告失败而非“已取消”。
- 超时后取回该轮 token 用量；提示发出前的取消不会丢失；默认模型同样检查推理强度。

### 任务生命周期

- 任务结果在服务端确认前随心跳重发；`started` 在重连后补发。
- 重连时服务端立即续租在跑任务，收回断线期间被重新排队的任务（不会跑两次），重新排队从未送达的派发。
- 事件分批发送，只确认到连续存下的序号，缺口由重发补齐。
- 对 Agent 提问的回答在重连后重发；机器繁忙时回复 `RUNTIME_BUSY`，服务端 15 秒后重派。
- 实测：任务运行中重启服务端，任务照常完成。

- GitHub / GitLab / Bitbucket 仓库地址的路径不区分大小写。
